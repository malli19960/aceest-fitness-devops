Docker execution on the Linux assignment VM

Run these commands in a terminal inside the Linux assignment VM, from the cloned project directory. Starting Docker activates the daemon; it does not automatically give every service account permission to use Docker.

sudo systemctl start docker
systemctl is-active docker
id -nG

# Build and test the test image
docker build --target test -t aceest-fitness:test .
docker run --rm aceest-fitness:test

# Build, launch, smoke-test on host port 5000, then clean up
docker build --target runtime -t aceest-fitness:latest .
docker run -d --name aceest-fitness-runtime -p 5000:5000 aceest-fitness:latest
curl -i http://127.0.0.1:5000/health
curl -i "http://127.0.0.1:5000/api/plan?weight=70&height=175&age=30&gender=male&activity=moderate&goal=fat_loss"
docker stop aceest-fitness-runtime
docker rm aceest-fitness-runtime

In the VM, the interactive account had Docker group access. The test image reported 33 passing tests; both runtime endpoints returned HTTP 200 on host port 5000, and the temporary container was stopped and removed. This port-5000 execution was rerun and verified on 11 October 2026; the screenshots below show the earlier successful Docker build/test/runtime validation (which used port 5050).

How to execute

1. Set up Python (PowerShell)

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt

The current GUI demo uses the project runtime dependencies; no additional GUI packages are needed.

Tkinter is included with the standard Windows Python installer when Tcl/Tk support is selected.

2. Run the main Flask app

python app.py

Browse to http://127.0.0.1:5000/health or run curl.exe http://127.0.0.1:5000/health. Stop with Ctrl+C.

3. Run a progressive Flask snapshot

python .\Versionspp_v1_0.py
# Stop it with Ctrl+C before starting another snapshot
python .\Versionspp_v5_0.py

Snapshots run as standalone scripts on port 5000; run one at a time. Available versions: app_v1_0.py, app_v1_1.py, app_v2_0.py, app_v2_1.py, app_v3_0.py, app_v3_1.py, app_v4_0.py, and app_v5_0.py.

4. Run the desktop GUI demo

python .itness_gui_demo.py

It opens the desktop client and runs a local Flask API on a temporary port; no separate Flask process is needed. Close the window to stop the API.

5. Repeat validation

python -m pytest -q
python -m compileall -q app.py tests Versions fitness_gui_demo.py

Jenkins VM configuration and run

To execute the pipeline in Jenkins:

  1. Sign in to Jenkins in the Linux VM and open the ACEest Fitness Gym-CI job.
  2. For job configuration, use Pipeline script from SCM, SCM Git, repository https://github.com/malli19960/aceest-fitness-devops.git, branch */main, script path Jenkinsfile. Save the job.
  3. Choose Build Now to run it manually; open the new build number and Console Output to see checkout and stage results.
  4. For push-triggered builds, enable GitHub hook trigger for GITScm polling and configure the GitHub webhook to call https://<jenkins-host>/github-webhook/.

The pipeline stages in Jenkinsfile execute in sequence: build the test image, run Pytest in that image, then build the runtime image. The job description is ?Builds and tests the ACEest Fitness application using Docker, then builds the runtime image.?

Successful Jenkins Build #9 evidence

After Docker group membership was applied to the Jenkins service and Jenkins restarted, the job ran successfully. These screenshots show the result, the 33-test container stage, and the final pipeline status.

Resolution and verification: an administrator added jenkins to the docker group and restarted the Jenkins service to refresh its supplementary groups. The approved administrator commands were:

sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
id jenkins
sudo -u jenkins docker info --format '{{.ServerVersion}}'

id jenkins then showed the docker group, and Docker Engine verification returned version 27.5.1. Jenkins Build #9 then completed all pipeline stages with SUCCESS; its container test stage passed all 33 tests and the runtime image built successfully. The earlier Build #2 screenshot above records the permission issue before this fix. Security: Docker-group membership grants effectively root-level host control; use only with administrator approval, or use an isolated Docker-capable agent.
